# 웨이퍼 결함탐지 및 청결도 검사

웨이퍼 표면 영상에서 결함의 위치와 종류를 검출하고, 입자·오염의 분포를 측정해 청결도 검사를 지원하는 것을 목표로 한다. 현재는 공개 현미경 이미지 기반 결함 검출 앱과 추가 학습 기록이 있으며, 청결도 지표와 실제 촬영 조건을 정하는 단계다.

## 현재 상태

| 구분 | 확인한 내용 | 다음 작업 |
|---|---|---|
| 결함 검출 | 이미지 업로드, 6종 결함 검출, 타일 추론, 결과·이력 저장 코드 반영 | 모델 준비 후 정상·결함 영상 평가 |
| 추가 학습 | 공개 이미지로 5에폭 추가 학습한 모델을 검증 데이터 기준으로 선택 | 새 웨이퍼와 촬영 조건에서 재평가 |
| 현장 데이터 | 데이터 등록·학습용 CLI와 카메라 촬영 API 구현 | 실제 촬영 자료와 별도 시험셋 확보 |
| 청결도 검사 | 오염 관련 결함 클래스 `stains_enbedded` 검출 지원 | 입자 수·오염 면적 등 지표와 합격 기준 정의 |
| 검사장치 | 수동 캐리어·XY 정지촬영 광학 헤드의 예비설계 기록 | 광학계 선정, 치수 확정과 제작 검토 |

청결도 전용 지표와 판정 기준은 구현 전이다. 실제 장치 성능과 정상 영상만의 오경보율도 추가 검증이 필요하다. 하드웨어 기록의 상태는 제작 전 예비설계다.

## 기존 결함 검출 결과

공개 데이터의 분할은 train 1,472장, val 275장, test 287장이다. 검출 클래스는 `edge_bite`, `gray_line`, `open`, `scratch`, `short_circuit`, `stains_enbedded`의 6종이며, 식별자는 원자료의 철자를 유지한다.

아래 값은 **2026-09-30에 저장된 평가 기록**을 정리한 것이다. 단위는 %이며 모델 선택 기준은 검증 데이터의 mAP50–95다.

| 모델 | val mAP50 | val mAP50–95 | 기존 test mAP50 | 기존 test mAP50–95 |
|---|---:|---:|---:|---:|
| 기준 모델 | 71.93 | 35.39 | 73.73 | 36.42 |
| 5에폭 추가 학습 | 72.40 | 36.56 | 76.74 | 37.66 |

test는 이전에 확인한 R01 분할을 다시 사용한 개발 평가다. 새로운 독립 시험 결과와 구분해야 하며, 정상 웨이퍼의 오경보율·실제 장치 성능·청결도 판정 정확도는 이 수치로 확인할 수 없다.

세부 수치와 원본 파일의 SHA256은 [평가 근거](근거/웨이퍼검사_평가근거_2026-10-15_검토본_v01.json)에 정리했다.

## 다음 작업

1. 정리한 앱 소스와 설치 안내에 따라 실행 환경과 모델을 준비하고, 이미지 입력부터 결과 저장까지 확인한다.
2. 정상·결함·오염 영상을 웨이퍼와 촬영 세션 단위로 구분해 수집하고, 별도 시험셋을 확보한다.
3. 청결도 지표와 측정 단위를 정한 뒤 입자 수·오염 면적을 계산한다. 실제 면적 환산에는 촬영 배율과 픽셀 크기 보정이 필요하다.
4. 시험셋에서 결함별 검출 성능, 정상 영상 오경보율, 청결도 측정 오차를 확인하고 앱에 판정 결과를 연결한다.

단계별 산출물과 완료 기준은 [간단한 개발 계획](계획/웨이퍼검사_개발계획_2026-10-15_초안_v01.md)을 따른다.

## 설치와 실행

Windows와 Python 3.11 이상을 기준으로 한다. 저장소 폴더에서 PowerShell로 실행한다.

```powershell
powershell -ExecutionPolicy Bypass -File .\Setup.ps1
.\Start-Platform.cmd
```

검사 화면은 `http://127.0.0.1:8893`, API 안내는 `http://127.0.0.1:8893/docs`다. 설치 스크립트는 프로젝트 안의 `.venv`에 CPU용 PyTorch와 필요한 패키지를 설치한다. 앱 추론은 CPU를 사용하며, 기존 추가 학습 스크립트는 CUDA 환경을 별도로 요구한다.

모델 가중치는 별도로 준비한다. 기존 6종 기준 모델을 `models/baseline.pt`, 추가 학습 모델을 `models/finetuned.pt`에 두면 해당 모델을 선택할 수 있다. `models/registry.json`은 기존 모델의 식별 기록이며 가중치 파일을 대신하지 않는다. 모델이 없으면 화면과 API 상태를 확인할 수 있고 추론 버튼은 비활성화된다.

업로드한 이미지와 검사 결과는 `runtime/`에 저장된다. 데이터·가중치·실행 기록은 Git에 올리지 않는다. 자세한 입력·출력과 제한은 [API 안내](API.md)를 참고한다.

## 코드 구성과 검사

| 경로 | 내용 |
|---|---|
| `app.py`, `static/` | 로컬 검사 API와 한국어 화면 |
| `scripts/finetune.py` | 기존 공개 데이터 기반 추가 학습 |
| `scripts/prepare_field_data.py`, `scripts/finetune_field.py` | 현장 자료 등록·검수와 감사 기록을 확인하는 학습 절차 |
| `scripts/download_data.py` | 명시적으로 실행할 때 공개 데이터 취득·감사 |
| `tests/` | API 입력·경로 제한, 타일/NMS, 현장 자료 검수·변조·분할 검사 |
| `FieldData_inventory_template.csv` | 현장 자료 목록 양식 |

`download_data.py`의 기본 대상은 Carinthia-S다. `--wafer-cache`로 기존 감사된 Wafer-Datas 캐시를 가져올 수 있으며, 6종 데이터를 새로 다운로드하거나 자동으로 분할하지는 않는다. 기존 캐시의 manifest·준비 감사·독립 감사·취득 기록과 원본·가공 파일이 필요하다.

```powershell
.\.venv\Scripts\python.exe scripts/download_data.py --skip-carinthia --wafer-cache "<기존 wafer_r01 경로>"
```

이 절차는 현재 저장소 경로에 맞는 `data/wafer/data.yaml`과 감사 기록을 생성한다. 공개 데이터 추가 학습은 기존 고정 분할과 파일 SHA를 확인하므로, 새로 촬영한 자료는 `prepare_field_data.py`와 `finetune_field.py`의 별도 절차를 사용한다. 각 스크립트의 `--help`에서 입력 인자를 확인할 수 있다.

가중치 없이 API와 데이터 검증 테스트를 실행할 수 있다. 실제 모델 추론 테스트는 기본적으로 건너뛴다.

```powershell
$env:WAFER_REAL_INFERENCE='0'
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

2026-10-15 검증에서는 기존 Python 환경에서 API·데이터 검증 테스트 20건을 통과했고, 실제 모델 테스트 1건은 기본 설정대로 건너뛰었다. 별도 확인으로 기존 로컬 가중치를 읽어 합성 영상의 CPU 전체 프레임·타일 추론, 결과 이미지 조회와 이력 저장을 확인했다. 새 가상환경 전체 설치와 카메라·실제 웨이퍼 시험은 이번 검증에 포함하지 않았다.

검증 조건과 코드 SHA256은 [코드 검증 기록](근거/웨이퍼검사_코드검증_2026-10-15_검토본_v01.json)에 정리했다.
